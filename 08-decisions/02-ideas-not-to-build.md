# Ideas not to build

> This file is an index, not the source of truth. Full rationale lives in `01-decision-log.md` at the dated entry cited. Rows marked *Closed — platform* are technical constraints, not preferences: they will not become available by revisiting the design decision.

These ideas are excluded unless new evidence overturns the decision. `Status` is exactly one of:

- **Closed — philosophy** (conflicts with a Hold principle)
- **Closed — platform** (technically impossible for a third-party app; will not become possible by deciding differently)
- **Closed — assessed** (considered on merit, deliberately not pursued)
- **Superseded** (replaced by a later decision; link it)

## Must NOT be added to this file

**In-app "on Hold" presence indicator** (seeing when another Hold user is currently on Hold). `04-open-questions.md` (2026-08-19, sourced from a 2026-08-17 design session) states this is **open and constrained, not rejected** — technically possible, philosophically in tension with Hold's principles if built carelessly, but explicitly left open pending a visibility rule (never ambient, never discoverable, only visible to someone in the relevant Circle) rather than closed. It is also explicitly distinct from automatic cross-platform status syncing below — "different features, different constraints, not to be merged." Do not add this idea to the table below, and do not merge it with the status-syncing row.

## Notes on this rebuild

- **"Friends waiting" reminders and Gamified recovery, dropped from this file (2026-08-20).** Both were bare bullets in the previous version with no traceable source anywhere in either repo, confirmed by two independent sweeps (the original audit and a later synonym sweep covering "gamification," "achievement," "reward system," "points," "levels," "leaderboard," etc.). Confirmed by direct instruction that no rationale can be recalled for either — treated as stale carry-over rather than real rejected ideas, and removed rather than kept in an "unsourced" holding block.
- **`hold-app/docs/06-roadmap.md` has its own "Not on roadmap without new evidence" list, near-identical in spirit to this file, which the original sweep missed** (it checked `hold-app` for the specific Task 1 terms but not for the original 13 bullets under synonyms). A later pass found it and sourced four previously-unsourced items to it directly: Automatic replies, Public social profiles, and Recipient open tracking (all listed there verbatim or near-verbatim), plus Mandatory return dates via the separate `01-mvp-scope.md`. That roadmap list itself carries no dates or rationale beyond the bare phrases — same gap this file originally had — so "why excluded" for those four rows is reconstructed from the closest applicable Hold principle already documented elsewhere in the book, not transcribed from a source that explains itself.
- **Relationship health scores** — the sharpened reasoning above (2026-08-20) is being written into this book for the first time; it was not previously in `01-decision-log.md` or anywhere else, unlike the Task 1 additions above it, which are also mirrored there. Also added, by direct instruction, to `hold-app/docs/08-product-bible.md` as a named deliberate non-feature.
- **Automatic cross-platform status syncing and text-to-speech voicemail greeting — wording conflict resolved 2026-08-19, by direct instruction.** Both now use "closed, not deferred," the same convention already established for "Hold as default SMS handler." The voicemail item was previously written up as "deliberately scoped out of this pass" (deferred-sounding), which conflicted with the closure actually decided in the source chat ("mark voicemail as not a future spec") — `04-open-questions.md` corrected in place, plus a new dated entry in `01-decision-log.md` recording the reclassification.
- **AI-inferred health/mood labelling** — no specific dated decision-log entry could be located for this exact idea despite the fold-in instruction citing `01-decision-log.md`. Sourced instead to the general "infer relationship facts not supplied by the user" rule in `06-privacy-security/02-ai-boundaries.md`, which supports the same conclusion but isn't a dedicated entry about health/mood labelling specifically.
- **Community / social content feed** — `04-open-questions.md`'s Taking Time widget entry (2026-08-11) refers to this as "already explicitly rejected earlier in this project," but no earlier standalone rejection entry could be located independently. Sourced to the one place it's actually discussed in the book, with this caveat attached.
- **"Auto-converting trial" was not added, despite appearing in the original fold-in list.** Current pricing documentation (`07-business/02-pricing-principles.md`) states the opposite of "closed": the intro-priced Hold+ tier (£4.50/3-month at time of writing, since corrected 2026-08-20 from the original £4.99/3-month this note was written against — see "Pricing corrected 2026-08-20") **is**, by final decision, a paid introductory price that auto-converts to an ongoing subscription. Adding "auto-converting trial" as a closed/rejected idea would directly contradict the current, live pricing design regardless of the exact figure. Only the narrower, still-accurate claim — no **$0** free trial gates basic access — is included above as "Hold+ free trial."
